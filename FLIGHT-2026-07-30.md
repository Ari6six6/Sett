## Decisions, and why

**Checked DNS in the first thirty seconds.** Box #1 cost ~25 minutes to a host
that blocked UDP *and* TCP 53. `apt-get` hung at 0:00 CPU with no error, and
KM's `apt_wait`/`net_wait` shims could not recover because a hung process never
returns to be retried. That is now the first thing checked on any box.

**Parallelised the download against the build.** On box #1, llama-server's `-hf`
pull ran single-stream at 3.9 MiB/s — 80 minutes for 18 GB. Four parallel range
grabs got 5.9 MB/s *each*, proving a per-connection limit rather than a
bandwidth cap. So: install `hf_transfer`, pull separately, let llama-server find
a warm cache. Here that is 73 MiB/s and it overlaps the build entirely.

**Chose `glm-q4` first despite 48 GB of headroom.** It is the model measured
this morning. Holding it fixed makes the brief experiment a genuine comparison
instead of two unrelated numbers. Bigger models come after, as a second axis.

**Left `sett birth` to call `km`.** The GPU organ is not reimplemented. `sett`
shells out to it. That boundary is the whole reason this is not harness #16.

### Gate C, and the check that inverted

`sett gate` only ever implemented **Gate A**: run each check against an empty
out dir, demand it fail. That catches "a file appeared" checks. It does not
catch the subtler fake — a check that imports the artifact, never exercises
it, and passes against something with the right shape and the wrong behaviour.

`gate-c.sh` plants exactly that impostor: for every `$OUT/N.py` the spec names
it writes a module defining every function named in the `do:` line, each
returning `[]`; for `.sh` an executable that exits 0 with plausible output;
for `.json`/`.txt` a valid, wrong value. Then it runs the real check and
demands it still fail.

It is built on `points()` and `checks()` — two of the eight utilities the
dogfood gym produced. The gym output is now load-bearing.

Results:

| spec | gate A | gate C |
|---|---|---|
| code-10 | 10/10 | 10/10 |
| code-sett-8 | 8/8 | 8/8 |
| analyst-12 | 12/12 | 12/12 |
| stix-graph-12 | 12/12 | 12/12 |
| smoke-3 | 3/3 | **2/3 — one FAKE** |

**The fake, and why it matters more than the score.**

`smoke-3` point 3 asked for a count of `.probe` files under
`/home/michael/probe/specs`, and computed ground truth with `find` on that
same path. When `probe` was merged into SETT the directory ceased to exist.
`find` on a missing directory returns nothing, so the expected value silently
became `0`.

The check did not break. It **inverted**:

- the model's correct historical answer, `4`, now **FAILS**
- a garbage answer, `0`, now **PASSES**

`sett check smoke-3` confirms it: 2/3 PASS, point 3 FAIL — with the right
answer sitting in the out dir.

This is the drift class SETT was built to kill, found inside SETT's own
ledger, by SETT's own tooling. The endpoint-as-only-truth rule killed drift
between *what is pinned* and *what is served*. It said nothing about drift
between *what a check asserts* and *what still exists*.

Fix applied: the point now reads `/home/michael/SETT-repo/specs`, and the
check is guarded with `test -d` so a vanished corpus fails loudly instead of
collapsing to zero. The stale `3.txt` was deleted — the point is pending, not
passing.

**Rule earned:** a check that derives its expected value from the filesystem
must assert its source exists. Silent-zero is worse than a crash, because it
still prints PASS.

A mechanical audit of every `/home/` path named in every spec found no other
rot: all corpora are live.

### Pre-registered: is the noise mine?

Hypothesis: **ambiguous `do:` wording manufactures the flips.** When the spec
leaves an edge case unstated the model must guess, and it guesses differently
each run. That is a coin flip the operator built, not variance the model owns.

Evidence for it: point 6 is NOISY, and point 6 is the point already proven
underspecified — the `do:` never says what an empty list returns.

Test: rewrite the four NOISY points to state their edge cases, their argument
types, and (for 7) the invariant that makes the answer self-checkable. Every
added sentence must already be true of the existing check — **change what is
asked, never what is checked** — and the specs are re-gated on A and C

### Point 2, dissected — and a miss in my own de-ambiguation

Point 2 has now failed in nearly every run. Reading every version the model
wrote shows it is not one failure repeated. It is two disjoint bugs alternating:

| attempt | algorithm | parsing |
|---|---|---|
| bare law | **wrong** — counted every line, never grouped by id | right |
| repaired law | **right** — `last_verdicts={}`, last-wins per id | **wrong** — `parts[0]` as id, `parts[1]` as verdict |

state.tsv is `timestamp, id, verdict, note`, so `parts[1]` is the id. Every
line then fails the `in ('PASS','FAIL','ERROR')` guard, every line is skipped,
and the function returns all zeros. There is also a compiled-and-never-used
`^[A-Z]{4}$` regex in that version which would have excluded `ERROR` anyway,
being five letters.

The model can do the aggregation. The model can do the parsing. It has not yet
done both in the same run.

**And the reason is mine.** Point 1's `do:` states the layout outright —
*"tab-separated columns timestamp, id, verdict, note"*. Point 2's `do:` never
does; it says only "reads a SETT state.tsv". My de-ambiguation pass added the
argument type and the grouping rule to point 2 and **never added the column
layout** — I told it how to aggregate and not where the fields are.

So the pre-registered prediction "point 2 stays NOISY or DEAD" may well come
true for a reason that has nothing to do with capability. Recorded now, before
the runs land, so the story cannot be fitted afterwards.

This is the same lesson a third time in one day. The gym keeps reporting on the
operator:

  1. a check whose ground truth had been deleted
  2. a law naming a tool that no longer exists
  3. a point ambiguous about its edge case
  4. a point that never says where its own columns are

Four defects in the instructions, one genuine model weakness found so far
(bluffing a docstring it did not implement). That ratio is the actual finding
of the day, and it is not the one the gym was built to produce.
